# Блок требований: Интеграция软件 и HOST API

## Ссылка на требование: REQ-31 через REQ-35

### 1. Низкоуровневое программное обеспечение (Low-level Software)
- **Требование:** Кроссплатформенный драйвер (C/C++, Linux/Windows) для инициализации ПЛИС и непрерывного захвата кадров спектра по шине USB 3.0 без пропусков
- **Структурный блок:** Блок 8 «Программное обеспечение — HOST API»
- **Скрещивание с общими техническими требованиями:**
  - Требование ISO/IEC 25010 (стандарты качества ПО)
  - Совместимость с GNU Radio экосистемой
- **Сквозной расчет физики:** Результаты сквозного физического расчета (Δn ≈ 1.51×10⁻⁵, интенсивность ультразвука I_ac ≈ 18.6 Вт/м², глубина изменения индекса преломления) должны быть доступны через API для интеграции в систему мониторинга в реальном времени. Драйвер должен обеспечивать передачу комплексного потока панорамных данных с частотой считывания ≥50 кHz (строка) и разрешающей способностью пикселя ≥72 дБ.

### 2. Верхний уровень программного модуля (Upper-level Software Module)
- **Требование:** Наличие открытого программного модуля (Source block) для интеграции в экосистему GNU Radio для вывода комплексного потока панорамных данных в реальном времени
- **Структурный блок:** Блок 8.2 «GNU Radio Integration»
- **Скрещивание с общими техническими требованиями:**
  - Требование наличия Source block в GNU Radio
  - Совместимость с потоком данных форматов
- **Сквозной расчет физики:** Выходной фототок I_photo ≈ 0.888 мА (при P_laser = 5 мВт, η_opt ≈ 44.4%) должен конвертироваться в цифровой поток данных с разрядностью 14 бит (аналоговый эквивалент), обеспечивая динамический диапазон 85–100 дБ. Модуль должен реализовывать БПФ/FFT для математической обработки спектра на уровне CPU, а также аппаратную генерацию фаз синхронизации на ПЛИС.

### 3. Интерфейс USB 3.0 (USB 3.0 Interface)
- **Требование:** Непрерывный захват кадров спектра по шине USB 3.0 без потери кадров
- **Структурный блок:** Блок 8.3 «Data Transfer Interface»
- **Скрещивание с общими техническими требованиями:**
  - Требование USB 3.0 Type-C / PCIe Gen2 (интерфейс передачи данных)
  - Требование аппаратной генерации фаз синхронизации на ПЛИС
- **Сквозной расчет физики:** Частота считывания строк CMOS-матрицы ≥50 кГц требует пропускной способности шины USB 3.0 (теоретическая максимальная скорость 5 Гбит/с), которая должна обеспечить передачу данных от датчиков (2 фотодиода на 4.3 мм от оси Брэгга) без пропусков. Расчет пикового потока данных: 2048 пикселей × 14 бит × 50 кадров/с = 1.4 Мбит/с (устойчиво в рамках возможности USB 3.0).

### 4. Реальное время задержки (Real-time Latency)
- **Требование:** Аппаратное время задержки (Latency) фиксированное, ≤ 2.0 мкс
- **Структурный блок:** Блок 8.4 «Latency Control»
- **Скрещивание с общими техническими требованиями:**
  - Требование ГОСТ 24375-80 / ISO/IEC/IEEE 24748
  - Соответствие спецификации шага частотного разрешения ≤ 250 кГц
- **Сквозной расчет физики:** Время задержки связано с временем сканирования CMOS-матрицы (строка) и временем обработки данных на ПЛИС. При частоте считывания 50 кГц и 2048 пикселях время одного кадра составляет 20 мс, а аппаратная задержка на ПЛИС должна быть не более 2.0 мкс (0.01% от времени кадра), обеспечивая детерминированную передачу данных.

### 5. Совместимость с GNU Radio (GNU Radio Compatibility)
- **Требование:** Модуль должен быть 호환ible с текущей версией GNU Radio и открытыми источниками
- **Структурный блок:** Блок 8.5 «Ecosystem Integration»
- **Скрещивание с общими техническими требованиями:**
  - Требование открытого программного модуля (Source block)
  - Стандарт ISO/IEC 25010 качестве ПО
- **Сквозной расчет физики:** Интеграция должна обеспечивать вывод комплексного потока данных, полученных от акустооптического процессора, с параметрами: Δn (изменение индекса преломления), displacement (смещение), strain tensors (тензоры деформации) из результатов FEM-моделирования ElmerSolver. Плотность точек данных: эпсилон_zz_mean/max/min для кварцевого слоя и ноды трансформации.
